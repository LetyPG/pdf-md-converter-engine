# User Scenarios for pdf-to-md-engine-converter

## Purpose
These scenarios define the expected behavior of the system from the user's perspective.
They serve as:
* Product documentation;
* Acceptance criteria;
* Behavioral specifications;
* Inputs for validator acceptance tests;
* Regression scenarios.
The Markdown generated by this tool is an intermediate knowledge artifact and not the final intelligence layer.

---
# System Requirements

## Functional Requirements

### **When to Use This Tool**

| Scenario | Description |
|---|---|
| **CLI conversion** | Convert a single PDF from the command line and inspect the result |
| **Web UI Dashboard** | Visually upload PDFs, inspect metadata, and download artifacts via Streamlit |
| **RAG preparation** | Transform technical PDFs into structured Markdown for local RAG ingestion |
| **Agent knowledge assets** | Build safe, structured knowledge repositories for agent systems |
| **Library integration** | Invoke the pipeline programmatically within another project |
| **Documentation pipelines** | Automate PDF-to-Markdown as part of a local documentation workflow |

## Non-functional requirements and Error Handling

### **When NOT to use this tool**

| Limitation | Reason |
|---|---|
| **Scanned PDFs (image-only)** | No OCR engine is included; text layer must be present |
| **Password-protected PDFs** | Encrypted files are rejected at the preprocessing stage |
| **PDFs larger than 10 MB** | Enforced size limit for performance and memory safety |
| **Batch processing (multiple PDFs)** | Current implementation processes one PDF per invocation |
| **Extracting images or diagrams** | Images are not embedded; diagrams produce a text placeholder |
| **Preserving hyperlinks or URLs** | All URLs, hyperlinks, and email addresses are stripped (security gate) |
| **Raw HTML preservation** | HTML tags are removed from output (security gate) |

### **What the Converter Will Not Include in Output**

The following content is deliberately **removed** from the generated Markdown. This is both a **security restriction** and a **performance decision**:

| Content type | Reason removed |
|---|---|
| URLs (`https://...`) | Security gate — unsafe references excluded from knowledge artifacts |
| Hyperlinks (`[text](url)`) | Security gate — prevents malicious link propagation into agent contexts |
| Email addresses | Security gate — privacy protection |
| Raw HTML tags (`<tag>`) | Security gate — prevents HTML injection in downstream renderers |
| Markdown image syntax (`![](...)`) | Security gate — no image binary data is extracted or embedded |
| Embedded images / raster graphics | Performance decision — no image processing at runtime |
| Diagrams and charts | Performance decision — represented as `[Diagram detected but not reconstructed]` |
| Figures | Performance decision — represented as `[Figure omitted: <caption>]` |

> **Note:** These restrictions are enforced at two points in the pipeline: during extraction (Stage 2) and again during Markdown generation (Stage 3). The Quality Validator (Stage 4) independently verifies that no unsafe content reached the final output.

# US-001 — Convert a PDF using the CLI
## User Story
As a developer,
I want to convert a PDF into Markdown through the command line,
So that I can review, edit, and version-control the resulting document manually.
### Business Value
Provides a lightweight local workflow requiring no additional integrations.
### Preconditions
* The converter is installed locally.
* The input PDF exists.
* The PDF satisfies preprocessing constraints.
### Acceptance Criteria
**Scenario: Successful CLI conversion**
```gherkin
Given a valid PDF file named "manual.pdf"
And the PDF passes preprocessing validation
When the user executes:
  """
  pdf2md manual.pdf
  """
Then the conversion SHALL complete successfully
And a Markdown artifact SHALL be generated
And a validation report SHALL be generated
And the Markdown SHALL be human-readable
And the Markdown SHALL contain no URLs, hyperlinks, or email addresses
```
**Scenario: Reject oversized PDF**
```gherkin
Given a PDF larger than 10 MB
When the user executes:
  """
  pdf2md oversized.pdf
  """
Then the conversion SHALL be rejected
And no Markdown artifact SHALL be generated
And the rejection reason SHALL be "FILE_TOO_LARGE"
```
### Expected Artifacts
```txt
manual.md
validation.json
```

# US-002 — Prepare Markdown assets for RAG ingestion
## User Story
As an AI engineer,
I want to transform technical PDFs into Markdown,
So that they can later be indexed by local RAG pipelines.
### Business Value
Allows reuse of existing documentation without cloud processing.
### Preconditions
* Valid PDFs are available.
* Downstream chunking and vectorization systems are external.
### Acceptance Criteria
**Scenario: Generate RAG-ready Markdown**
```gherkin
Given a valid technical PDF
When the PDF is converted
Then the Markdown SHALL preserve headings
And lists SHALL preserve ordering
And tables SHALL preserve their structure
And diagrams SHALL be represented as placeholders
And the output SHALL be valid Markdown
And the output SHALL contain no URLs, hyperlinks, or email addresses
```
**Scenario: Preserve semantic structure**
```gherkin
Given a technical PDF containing sections and subsections
When conversion completes
Then heading hierarchy SHALL be preserved
And reading order SHALL be preserved
And the generated Markdown SHALL be deterministic
```
### Expected Artifacts
```txt
technical_doc.md
validation.json
```

# US-003 — Convert documentation into agent knowledge assets
## User Story
As an agent developer,
I want to convert documentation into Markdown knowledge assets,
So that agents can consume reusable procedural knowledge.
### Business Value
Enables the creation of secure and reusable knowledge repositories.
### Preconditions
* Vendor documentation is available as PDF.
* Agents consume Markdown downstream.
### Acceptance Criteria
**Scenario: Produce safe knowledge artifacts**
```gherkin
Given a vendor PDF containing documentation
When the conversion completes
Then the Markdown SHALL be human-readable
And the Markdown SHALL preserve semantic structure
And all URLs SHALL be omitted
And all hyperlinks SHALL be omitted
And all email addresses SHALL be omitted
And no raw HTML SHALL be emitted
```
**Scenario: Preserve instructional content**
```gherkin
Given a PDF containing procedures expressed as lists
When conversion completes
Then ordered steps SHALL preserve their sequence
And unordered lists SHALL preserve membership
```
### Expected Artifacts
```txt
knowledge_asset.md
validation.json
```

# US-004 — Use the converter as an embedded library
## User Story
As a developer,
I want to invoke the converter programmatically,
So that it can be integrated into local projects and workflows.
### Business Value
Supports extensibility beyond CLI execution.
### Preconditions
* The converter package is installed.
* The consuming application has filesystem access.
### Acceptance Criteria
**Scenario: Successful API invocation**
```gherkin
Given a valid PDF file
When the application invokes the conversion API
Then the conversion SHALL complete successfully
And the API SHALL return conversion results
And validation findings SHALL be returned
And no direct process termination SHALL occur
```
**Scenario: Handle recoverable warnings**
```gherkin
Given a valid PDF with mixed layouts
When conversion completes
Then Markdown SHALL still be generated
And warnings SHALL be returned to the caller
And warnings SHALL not terminate execution
```
### Expected Artifacts
```python
ConversionResult
ValidationReport
```

I want multi-column documents to preserve logical reading order,
So that the resulting Markdown remains understandable.
### Business Value

### Preconditions
The PDF contains multi-column pages.
The preprocessor identifies the layout correctly.
### Acceptance Criteria
**Scenario: Reconstruct multi-column documents**
```gherkin
Given a PDF classified as "MULTI_COLUMN"
When extraction is performed
Then logical reading order SHALL be reconstructed
And the resulting Markdown SHALL preserve document meaning
And validation thresholds for reading order SHALL pass
```
### Expected Artifacts
```txt
scientific_paper.md
validation.json
```

# US-006 — Enforce Markdown security gates
## User Story
As a user consuming Markdown through local LLMs and agents,
I want unsafe references removed,
So that generated knowledge artifacts reduce exposure to malicious content.
### Business Value
Reduces the risk of propagating unsafe artifacts into downstream systems.
### Preconditions
The extracted content contains unsafe references.
### Acceptance Criteria
**Scenario: Remove unsafe references**
```gherkin
Given extracted content containing URLs
And hyperlinks
And email addresses
When Markdown generation occurs
Then URLs SHALL be omitted
And hyperlinks SHALL be omitted
And email addresses SHALL be omitted
```
**Scenario: Remove unsafe markup**
```gherkin
Given extracted content containing raw HTML
Or Markdown image syntax
When Markdown generation occurs
Then raw HTML SHALL not be emitted
And Markdown image syntax SHALL not be emitted
```
### Expected Artifacts

```txt
safe_output.md
validation.json
```
